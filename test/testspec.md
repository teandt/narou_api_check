# なろうAPIツール テスト仕様書

本ドキュメントは、なろうAPIツールの各スクリプトに対するテスト仕様をまとめています。

## テスト対象スクリプト

1. `narou_api_main.py` - なろうAPIからのデータ取得
2. `narou_json2db.py` - JSONファイルからDBへのデータ登録
3. `narou_main.py` - 統計情報グラフ化処理
4. `db_func.py` - DB接続機能
5. `narou_func.py` - グラフ化関数群

---

## 1. narou_api_main.py テスト仕様

### 概要
なろうAPIから全小説データを取得し、JSONファイルに出力するスクリプト。

### 機能仕様
- なろうAPIから作品総数を取得
- 最新の作品データを500件ずつ取得（重複排除）
- JSONファイル形式 `{"0": {...}, "1": {...}}` で出力
- `-o` オプションで出力ファイル名を指定可能（デフォルト: temp.json）

### テストケース

#### 正常系

| ID | テスト項目 | 入力 | 期待結果 | 備考 |
|----|----------|------|--------|------|
| T1-1 | デフォルト出力ファイル名 | オプションなし | temp.json が生成される | - |
| T1-2 | カスタム出力ファイル名 | `-o output.json` | output.json が生成される | - |
| T1-3 | 作品総数取得 | - | API から allcount > 0 が取得できる | - |
| T1-4 | JSON形式の正確性 | - | 出力JSONが有効な形式である | キーが "0", "1", ... の連番 |
| T1-5 | 必須フィールド確認 | - | すべてのレコードに ncode が存在 | - |
| T1-6 | 重複排除 | - | 重複する ncode がない | 同じ作品は1回のみ出力 |
| T1-7 | データ整合性 | - | 出力されたデータに NULL や不正な値がない | - |
| T1-8 | エンコーディング | - | 出力JSONが UTF-8 で正しくエンコード | 日本語が含まれる |

#### 異常系

| ID | テスト項目 | 入力 | 期待結果 | 備考 |
|----|----------|------|--------|------|
| T1-E1 | API接続エラー時のリトライ | ネットワーク障害 | 最大5回までリトライして処理 | 10秒待機後にリトライ |
| T1-E2 | API接続失敗時の終了 | 5回すべてのリトライ失敗 | エラーメッセージを出力して exit(1) | - |
| T1-E3 | データベース接続エラー | DB接続失敗 | エラーハンドリング実施 | check_count() の失敗 |
| T1-E4 | ディスク容量不足 | ディスク満杯 | IOError をキャッチして適切に処理 | - |

### パフォーマンス要件

| 項目 | 要件 | 説明 |
|------|------|------|
| 処理時間 | 約2時間 | API応答速度に依存 |
| 出力ファイルサイズ | 約1.75GB（2025/09実績） | 実行環境により変動 |
| 推奨メモリ | 4GB以上 | 余裕を持って配置 |

## 2. narou_json2db.py テスト仕様

### 概要
JSONファイルから MySQL に小説データを登録するスクリプト。

### 機能仕様
- JSONファイルをストリーミング読み込み
- データベースにバッチ登録（1000件ごと）
- カウンター更新
- タイムスタンプ記録
- `-i` オプションで入力ファイルを指定可能（デフォルト: temp.json）
- エラー時は自動ロールバック、成功時はコミット

### テストケース

#### 正常系

| ID | テスト項目 | 入力 | 期待結果 | 備考 |
|----|----------|------|--------|------|
| T2-1 | デフォルト入力ファイル | オプションなし | temp.json が読み込まれる | - |
| T2-2 | カスタム入力ファイル | `-i custom.json` | custom.json が読み込まれる | - |
| T2-3 | データベースへの登録 | 有効なJSONファイル | contents_tbl に全データが登録される | - |
| T2-4 | カウンター更新 | - | parameter_tbl のカウンターがインクリメント | - |
| T2-5 | タイムスタンプ記録 | - | count_timestamp_tbl にタイムスタンプが記録 | ISO 8601形式 |
| T2-6 | バッチ処理 | 1000件以上のデータ | 1000件ごとにバッチ登録 | 効率的なinsert処理 |
| T2-7 | トランザクション正常終了 | - | すべてのデータがコミットされる | - |
| T2-8 | 必須フィールド検証 | - | ncode が必須フィールドとして検証される | - |

#### 異常系

| ID | テスト項目 | 入力 | 期待結果 | 備考 |
|----|----------|------|--------|------|
| T2-E1 | ファイルが見つからない | 存在しないJSONファイル | FileNotFoundError をキャッチしてexit(1) | - |
| T2-E2 | 不正なJSON形式 | 破損したJSONファイル | JSONパースエラーをキャッチ | - |
| T2-E3 | ncode 欠落レコード | ncode がないデータ | Exception 発生、ロールバック実施 | - |
| T2-E4 | DB接続エラー | DB接続失敗 | エラーメッセージを出力、ロールバック | - |
| T2-E5 | SQL実行エラー | 不正なデータ型 | ロールバック実施 | 制約違反など |
| T2-E6 | 空のJSONファイル | `{}` のみ | 正常に処理完了（登録データなし） | - |
| T2-E7 | カウンター値が -1 | check_count() が -1 を返す | エラーメッセージ出力して exit(1) | - |

### パフォーマンス要件

| 項目 | 要件 | 説明 |
|------|------|------|
| 処理メモリ | 4GB以上 | 大規模JSONファイル処理 |
| バッチサイズ | 1000件 | I/O効率の最適値 |

## 3. narou_main.py テスト仕様

### 概要
データベースのデータを使用して、統計情報をグラフ化するスクリプト。

### 機能仕様
- コマンドライン引数で処理を選択
- 3つの異なるグラフ化処理をサポート
- 生成グラフは `img/` ディレクトリに保存

### テストケース

#### 正常系 - オプション: `-lm` (タイトル長平均)

| ID | テスト項目 | 入力 | 期待結果 | 備考 |
|----|----------|------|--------|------|
| T3-1 | 複数年指定 | `-lm 2020 2024 100` | plot_top_2020_2024_100.png が生成される | 5年間のグラフ |
| T3-2 | 同一年指定 | `-lm 2024 2024 100` | X軸が2024年のみ表示 | - |
| T3-3 | 大きいLIMIT指定 | `-lm 2020 2024 10000` | TOP 10000件を対象にグラフ化 | - |
| T3-4 | 小さいLIMIT指定 | `-lm 2024 2024 1` | TOP 1件のみを対象にグラフ化 | - |
| T3-5 | グラフの軸設定 | - | X軸: 年、Y軸: タイトル長平均、上限50 | - |

#### 正常系 - オプション: `-lh` (タイトル長ヒストグラム)

| ID | テスト項目 | 入力 | 期待結果 | 備考 |
|----|----------|------|--------|------|
| T3-6 | ヒストグラム生成 | `-lh 2024 100` | hist_2024_100.png が生成される | - |
| T3-7 | 統計情報表示 | - | タイトル長の mean, std, min, max が表示 | describe() 結果 |
| T3-8 | グラフ範囲 | - | X軸は0～100に設定 | - |

#### 正常系 - オプション: `-nt` (連載/短編数)

| ID | テスト項目 | 入力 | 期待結果 | 備考 |
|----|----------|------|--------|------|
| T3-9 | 連載/短編グラフ | `-nt 2015 2024` | nobel_type_2015-2024.png が生成される | - |
| T3-10 | 複数年集計 | - | 指定年全年のデータが集計される | - |
| T3-11 | 凡例表示 | - | グラフに "long", "short" の凡例が表示 | - |

#### 異常系 - 入力値検証

| ID | テスト項目 | 入力 | 期待結果 | 備考 |
|----|----------|------|--------|------|
| T3-E1 | 年の4桁確認 | `-lm 20 2024 100` | ArgumentTypeError で処理中止 | 3桁年 |
| T3-E2 | 不正な年 | `-lm 2099 2024 100` | エラーメッセージを表示 | 開始年 > 終了年 |
| T3-E3 | LIMIT_COUNTが0 | `-lm 2024 2024 0` | ValueError で処理中止 | - |
| T3-E4 | LIMIT_COUNTが負数 | `-lm 2024 2024 -1` | ValueError で処理中止 | - |
| T3-E5 | 不正な年形式 | `-lm 202a 2024 100` | ArgumentTypeError で処理中止 | 非数値を含む |
| T3-E6 | LIMIT_COUNTが非数値 | `-lm 2024 2024 abc` | ValueError で処理中止 | - |
| T3-E7 | DB接続エラー | - | 適切なエラーメッセージを表示 | - |

#### 異常系 - ロジック検証

| ID | テスト項目 | 入力 | 期待結果 | 備考 |
|----|----------|------|--------|------|
| T3-E8 | X軸ステップ計算 | `-lm 2020 2024 100` | step > 0 で計算される | 差が小さい場合の対応 |
| T3-E9 | 単一年のステップ | `-lm 2024 2024 100` | X軸が [2024] のみ | - |

## 4. db_func.py テスト仕様

### 概要
データベース接続機能を提供するモジュール。

### 機能仕様
- `.env` ファイルから DB 設定を読み込み
- PyMySQL を使用して MySQL に接続
- DictCursor で結果を辞書形式で返す

### テストケース

#### 正常系

| ID | テスト項目 | 入力 | 期待結果 | 備考 |
|----|----------|------|--------|------|
| T4-1 | DB接続成功 | 正しい.env設定 | pymysql.Connection オブジェクトが返される | - |
| T4-2 | 接続設定確認 | - | host, port, user, password, database が正しく設定 | - |
| T4-3 | 文字セット確認 | - | charset が utf8mb4 に設定 | - |
| T4-4 | DictCursor確認 | - | 結果が辞書形式で返される | - |

#### 異常系

| ID | テスト項目 | 入力 | 期待結果 | 備考 |
|----|----------|------|--------|------|
| T4-E1 | .env ファイルが見つからない | .env なし | 環境変数から値を読み込む | - |
| T4-E2 | 必須環境変数が未設定 | DB_HOST 未設定 | KeyError または接続エラー | - |
| T4-E3 | DB接続失敗 | 接続できないホスト | pymysql.Error が発生 | - |
| T4-E4 | ポート番号が非数値 | DB_PORT="abc" | ValueError 発生 | - |

### 概要
グラフ化処理と統計分析を行うモジュール。

### 機能仕様
- タイトル長のヒストグラム生成
- タイトル長の年別平均計算
- 連載/短編の年別投稿数集計

### テストケース

#### 正常系 - get_title_length_hist()

| ID | テスト項目 | 入力 | 期待結果 | 備考 |
|----|----------|------|--------|------|
| T5-1 | ヒストグラム生成 | check_year=2024, limit_size=100 | img/hist_2024_100.png が生成 | - |
| T5-2 | データ抽出SQL | - | WHERE 句で年度範囲を正確に指定 | - |
| T5-3 | TOP N件取得 | limit_size=100 | 総合ポイント上位100件のみ対象 | - |
| T5-4 | 統計情報出力 | - | describe() で mean, std, min, max 表示 | - |

#### 正常系 - get_title_length_mean()

| ID | テスト項目 | 入力 | 期待結果 | 備考 |
|----|----------|------|--------|------|
| T5-5 | 複数年平均計算 | start_year=2020, end_year=2024 | 各年のタイトル長平均が計算される | - |
| T5-6 | 年別プロット | - | img/plot_top_2020_2024_100.png が生成 | - |
| T5-7 | X軸目盛り計算 | 5年間 | step = (2024-2020)/5 で計算 | - |
| T5-8 | 単一年の場合 | start_year=2024, end_year=2024 | X軸が 2024 のみ表示 | - |

#### 正常系 - get_nobel_type_nums()

| ID | テスト項目 | 入力 | 期待結果 | 備考 |
|----|----------|------|--------|------|
| T5-9 | 連載/短編集計 | start_year=2015, end_year=2024 | img/nobel_type_2015-2024.png が生成 | - |
| T5-10 | 連載数カウント | novel_type=1 | 連載作品のみカウント | - |
| T5-11 | 短編数カウント | novel_type=2 | 短編作品のみカウント | - |
| T5-12 | 凡例表示 | - | グラフに "long", "short" が表示 | - |

#### 異常系

| ID | テスト項目 | 入力 | 期待結果 | 備考 |
|----|----------|------|--------|------|
| T5-E1 | DB接続エラー | DB接続失敗 | エラーメッセージを出力して処理終了 | - |
| T5-E2 | 該当データなし | limit_size > 実際のデータ数 | 取得可能な分のみ処理 | - |
| T5-E3 | SQL実行エラー | 不正なクエリ | pymysql.Error をキャッチ | - |
| T5-E4 | img ディレクトリなし | img/ が存在しない | FileNotFoundError が発生 | - |

## 環境要件

### システム要件
- OS: Ubuntu 24.04.3 LTS（確認済み）
- Python: 3.12.3
- Docker: MySQL 実行用

### 依存パッケージ

| パッケージ | 用途 |
|-----------|------|
| PyMySQL | MySQL接続 |
| pandas | データ分析・操作 |
| matplotlib | グラフ化 |
| requests | HTTP通信（API呼び出し） |
| python-dotenv | 環境変数読み込み |
| ijson | JSONストリーミング処理 |

### 環境設定
- `.env` ファイルが必須
  - `DB_HOST`
  - `DB_PORT`
  - `MYSQL_USER`
  - `MYSQL_PASSWORD`
  - `MYSQL_DATABASE`

## テスト実行方法

### セットアップ
```bash
cd /home/tea/code/narou_api
source venv/bin/activate
docker compose up -d
```

### テストの実行
各テストケースについて、対応するスクリプトを実行して検証します。

```bash
# narou_api_main.py のテスト
python3 narou_api_main.py -o test_output.json

# narou_json2db.py のテスト
python3 narou_json2db.py -i test_output.json

# narou_main.py のテスト
python3 narou_main.py -lm 2020 2024 100
python3 narou_main.py -lh 2024 100
python3 narou_main.py -nt 2015 2024
```

### テスト結果記録

テスト実行結果は以下のファイルに記録します：
- `test/test_results.md` - テスト実行結果
- `test/test_log.txt` - 詳細ログ
